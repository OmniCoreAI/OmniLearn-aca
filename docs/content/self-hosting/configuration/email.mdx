# Email Configuration

OmniLearn supports two email providers for transactional email delivery: **Resend** and **SMTP**. Email is used for user invitations, password resets, and system notifications.

## Choosing a Provider

Set the email provider in your `.env` file using the `OMNILEARN_EMAIL_PROVIDER` variable:

```env
OMNILEARN_EMAIL_PROVIDER=resend   # or "smtp"
```

## Option 1: Resend

[Resend](https://resend.com) is a developer-friendly email API service.

```env
OMNILEARN_EMAIL_PROVIDER=resend
OMNILEARN_RESEND_API_KEY=re_your-resend-api-key
OMNILEARN_SYSTEM_EMAIL_ADDRESS=noreply@example.com
```

### Getting a Resend API Key

1. Create an account at [resend.com](https://resend.com)
2. Add and verify your sending domain
3. Generate an API key from the Resend dashboard
4. Copy the API key into your `.env` file

## Option 2: SMTP

You can use any SMTP server, including services like Amazon SES, Mailgun, or your own mail server.

```env
OMNILEARN_EMAIL_PROVIDER=smtp
OMNILEARN_SMTP_HOST=smtp.example.com
OMNILEARN_SMTP_PORT=587
OMNILEARN_SMTP_USERNAME=user@example.com
OMNILEARN_SMTP_PASSWORD=your-smtp-password
OMNILEARN_SMTP_USE_TLS=true
OMNILEARN_SYSTEM_EMAIL_ADDRESS=noreply@example.com
```

### SMTP Variables

| Variable | Description | Default |
|---|---|---|
| `OMNILEARN_SMTP_HOST` | SMTP server hostname | -- |
| `OMNILEARN_SMTP_PORT` | SMTP server port | `587` |
| `OMNILEARN_SMTP_USERNAME` | SMTP authentication username | -- |
| `OMNILEARN_SMTP_PASSWORD` | SMTP authentication password | -- |
| `OMNILEARN_SMTP_USE_TLS` | Enable TLS encryption | `true` |

## Applying Changes

After updating your email configuration, restart your instance:

```bash
omnilearn stop
omnilearn start
```

## System Email Address

The `OMNILEARN_SYSTEM_EMAIL_ADDRESS` is the "from" address used for all outgoing emails. When using Resend, this address must belong to a domain that is verified in your Resend account. When using SMTP, ensure the address is permitted by your SMTP server.

<Callout type="info">
If email is not configured, features like user invitations and password resets will not work. Users can still be created manually by an administrator.
</Callout>

## What Emails Are Sent

OmniLearn sends the following types of email:

- **User invitations** -- when an admin invites a user to join the platform or an organization
- **Password resets** -- when a user requests a password reset
- **System notifications** -- important system-level notifications
- **Academy notifications** -- enrollment, training assigned, course completed, certificate issued, session and assignment reminders

Each organization can replace these messages with its own templates, choose which events are sent, and review a delivery log under **Administration → Communication** (see [Email & SMS](/platform/administration/communication)). Without a custom template, the built-in email is sent unchanged.

## SMS

SMS notifications are optional and use one provider for the whole instance, chosen with `OMNILEARN_SMS_PROVIDER`:

| Provider | Use |
| --- | --- |
| `disabled` (default) | SMS messages are logged as *skipped* |
| `log` | Development: messages are written to the API log, not sent |
| `http` | Any SMS gateway with an HTTP API (for example a local Egyptian provider) |
| `twilio` | Twilio's REST API |

### Generic HTTP gateway

```bash
OMNILEARN_SMS_PROVIDER=http
OMNILEARN_SMS_HTTP_URL=https://sms.example.com/api/send
OMNILEARN_SMS_HTTP_METHOD=POST
OMNILEARN_SMS_HTTP_HEADERS='{"Authorization": "Bearer your-key"}'
OMNILEARN_SMS_HTTP_BODY='{"to": "{{to}}", "text": "{{message}}", "from": "{{sender}}"}'
OMNILEARN_SMS_HTTP_CONTENT_TYPE=application/json
OMNILEARN_SMS_SENDER=ACADEMY
```

`{{to}}`, `{{message}}` and `{{sender}}` are replaced in the body (JSON-escaped when the content type is JSON). Any 2xx response counts as sent. The gateway URL must be publicly reachable; private and internal addresses are blocked.

### Twilio

```bash
OMNILEARN_SMS_PROVIDER=twilio
OMNILEARN_TWILIO_ACCOUNT_SID=ACxxxxxxxx
OMNILEARN_TWILIO_AUTH_TOKEN=your-token
OMNILEARN_TWILIO_FROM=+15551234567
```

Phone numbers come from the member's profile. Egyptian numbers such as `01012345678` are normalized to `+201012345678`.
